# 유리함수 그래프 탐구 초당LAB

고등학교 공통수학의 `y = a/(x-p) + q (a ≠ 0)`를 조작하는 한국어 웹앱입니다. HTML·CSS·JavaScript와 브라우저 기본 Canvas만 사용합니다. 외부 CDN과 로그인은 없습니다. 학습 완료 여부는 현재 브라우저에 저장하며 학번·이름은 저장하지 않습니다. Google Sheets 전송은 아직 연결하지 않았습니다.

## 실행과 Preview

1. 프로젝트 최상위의 **`index.html`**을 Codex Preview로 엽니다. 이미 열어 두었다면 새로고침하거나 닫았다가 다시 여세요.
2. 기본 그래프 `y = 2/x`, 좌표평면과 a·p·q 슬라이더가 보입니다. 활동 1에서는 p·q가 0으로 고정됩니다.
3. 상단의 활동을 바꾸고 그래프를 관찰한 뒤 아래 카드에서 답 하나를 선택하세요. 선택하면 해당 문항의 **정답 확인하기** 버튼이 활성화됩니다.
4. 버튼을 누르면 정오답과 정답·해설이 표시됩니다. 다른 답을 선택하면 다시 확인할 수 있습니다.

`index.html`은 CSS·JavaScript가 포함된 단일 실행 파일이므로 별도의 파일 로딩이 필요 없습니다. 일반 브라우저에서 파일을 직접 열 수도 있습니다. `tools/index.template.html`은 편집용 틀이므로 Preview 대상으로 열지 마세요.

로컬 서버를 사용하려면 Python 3을 설치하고 프로젝트 폴더에서 실행합니다.

```sh
python3 -m http.server 8000
```

Windows에서는 `py -m http.server 8000`도 됩니다. 브라우저에서 `http://localhost:8000`을 열고, 서버 종료는 터미널에서 Ctrl+C를 누릅니다. 이 서버는 파일 제공만 하며 답안을 저장하지 않습니다.

화면에 “그래프를 준비하고 있습니다”가 계속 보이면 초기화가 완료되지 않은 상태입니다. 미리보기 자체에서 JavaScript 실행을 금지한 경우에는 일반 브라우저의 로컬 서버로 실행하세요.

## 전체 완료와 전송 준비

모든 문항을 정답 확인하고 세 미션을 성공하면 요청된 완료 팝업이 자동으로 열립니다. 학번은 숫자 문자열로 처리해 앞자리 0을 보존하고, 이름은 한글로 입력합니다. 입력값은 저장하지 않습니다. 완료 판정은 브라우저 기록에 근거하며 서버에서 검증된 학습 결과가 아니라는 안내를 표시합니다.

현재 전송 주소는 비어 있어 **입력이 유효해도 전송 버튼은 비활성화**됩니다. 실제 주소에 임의로 연결하지 않았습니다. 준비된 함수는 서버의 저장 확인 응답을 검증하고, 중복·전송 중 잠금·실패 재시도를 처리합니다. 실제 Apps Script 연결과 CORS 왕복 검증은 다음 단계입니다. 상세 저장 범위와 서버 응답 계약은 [SUBMISSION_SETUP.md](SUBMISSION_SETUP.md)를 참고하세요.

같은 기기를 다른 학생이 사용할 때는 하단의 **학습 기록 초기화**를 누르고 시작하세요. 저장이 차단된 미리보기에서는 저장 불가 안내를 표시하며, 정상적인 GitHub Pages에서는 localStorage를 사용합니다.

```sh
node tests/progress.test.cjs
# Playwright·Chromium 필요, 외부 서버 없이 모의 응답으로 검사
node tests/completion.test.cjs
```

## 교과서형 수식과 그래프 레이블

함수 설정 카드의 모든 활동·미션은 `app.js`의 공통 `renderFormula`를 사용합니다. HTML과 CSS로 분자·분모를 위아래에 놓고 분수선을 그립니다. **KaTeX·MathJax 등 외부 수식 라이브러리를 사용하지 않아 CDN이나 웹 폰트 로딩이 필요 없습니다.** 기존 단일 `index.html` Preview에서도 그대로 작동합니다.

- 음수 a는 분수 앞에 −로, 분자는 |a|로 표시합니다.
- p<0이면 분모에 x+|p|, p>0이면 x−p, p=0이면 x만 표시합니다.
- q<0이면 뒤에 −|q|, q>0이면 +q를 붙이고 q=0이면 생략합니다. 0.5 간격 소수도 그대로 표시합니다.
- 스크린 리더에는 같은 의미의 한 줄 수식을 제공합니다. 화면에 보이는 분수는 CSS로 표시합니다.
- 그래프 좌표·함수 계산은 바꾸지 않고 레이블만 별도 층에 배치합니다. 목표점 → 점근선 → 축 이름 → 눈금 순으로 우선순위를 두고 겹침과 영역 밖 잘림을 피합니다.
- 레이블은 밝은 배경으로 곡선과 구분하며, 목표점 좌표가 떨어져 표시되면 빨간 가는 연결선으로 점과 연결합니다. 현재·목표 점근선이 같으면 `목표·현재 x = …`처럼 합쳐서 표시합니다.
- 축과 격자는 옅게, 현재 함수는 초록색, 비교 함수는 보라색, 현재 점근선은 황토색, 목표점·목표 점근선은 빨간색으로 구분합니다.
- 확대·이동·화면 크기 변경 때 레이블을 다시 배치합니다. 화면 밖의 점·점근선에는 레이블을 만들지 않고, 눈금은 읽기 공간이 부족하면 일부 생략합니다. 밀집한 곡선 뒤에도 글자가 읽히도록 배경을 둡니다.

## 활동별 구성

각 활동 화면은 정답 하나인 4지선다 3문항입니다. 활동 4는 미션마다 3문항이 달라 총 9문항이며, 전체 완료 기준은 객관식 18문항과 그래프 미션 3개입니다. 정답을 선택만 해서는 완료가 되지 않고 **정답 확인하기**를 눌러야 합니다. 계수 변경·활동 전환 시 보기 선택과 현재 해설은 초기화하지만, 이미 확인한 정답의 완료 표시와 미션 완료는 브라우저에 저장되어 새로고침 후에도 복원됩니다. 전체 기록은 **학습 기록 초기화**, 활동 4의 기록은 **처음부터 다시 도전**으로 지웁니다.

| 활동 | 기본 계수 (a, p, q) | 조작과 문항 |
| --- | --- | --- |
| 1. a의 변화 | (2, 0, 0) | a만 조작. 사분면, x=1의 함수값, 절댓값을 2배로 할 때의 변화 |
| 2. 평행이동 | (2, 1, −1) | a·p·q 조작. 비교 그래프 기본 표시. 가로 이동, 세로 이동, 대칭 중심 |
| 3. 점근선과 범위 | (−2, 1, 2) | a·p·q 조작. 점근선의 방정식, 정의역, 치역 |
| 4. 함수 만들기 | (1, 0, 0) | a·p·q 조작. 선택한 미션의 목표 p, 목표 q, 목표점 대입 식 |

활동 1~3에서는 문항의 정답 확인 후 현재 함수의 점근선 표시·숨기기를 사용할 수 있습니다. 활동 4는 목표 점근선을 처음부터 빨간 점선으로 표시하며, 현재 함수의 점근선도 별도 체크박스로 표시할 수 있습니다. 비교 그래프는 보라색 점선, 현재 함수는 초록색입니다.

## 활동 4의 간결한 화면 배치

활동 4에서만 **활동 메뉴 → 목표 그래프 만들기 → 그래프·함수 설정 → 객관식 탐구** 순서로 표시합니다. 기존의 중복 활동 안내는 이 화면에서만 숨기고, 활동 1~3의 안내·배치는 유지합니다.

미션 카드 첫 줄은 제목과 진행 상황, 둘째 줄은 미션 선택, 셋째 줄은 현재 조건, 넷째 줄은 확인·해설·다음 미션·재도전 버튼입니다. 실패·성공 안내와 공개된 정답 해설은 그 아래에서 작은 여백으로 표시합니다. 넓은 화면에서는 조건과 버튼이 각각 한 줄이고, 좁은 화면에서는 줄바꿈합니다. 버튼 높이는 44px 이상이며 그래프의 기존 높이는 줄이지 않았습니다.

이 배치 수정은 `tools/index.template.html`, `style.css`와 생성된 `index.html`에만 적용되며 `app.js`·`math.js`는 수정하지 않았습니다. 1280·820·768px에서 초기 미션 카드 높이 약 234px, 조건 한 줄과 버튼 가로 배치를 확인했습니다. 390·320px에서는 조건이 두 줄이며 버튼은 겹치거나 잘리지 않고 줄바꿈합니다.

레이아웃 회귀 검사는 개발용 Playwright·Chromium이 있으면 서버 없이 실행할 수 있습니다.

```sh
node tests/mission-layout.test.cjs
```

수정 직전 기록한 주요 요소의 좌표·크기와 비교하여 활동 1~3의 배치가 1280·820·768·390px에서 그대로임을 확인했습니다. 검사 화면 캡처는 `/tmp/lab-mission-layout-1280.png`, `/tmp/lab-mission-layout-768.png`, `/tmp/lab-mission-layout-390.png`에 생성됩니다.

## 활동 4: 순차 잠금 챌린지

| 미션 | 난이도 | 목표 점근선 | 빨간 목표점 |
| --- | --- | --- | --- |
| 1 | 기본 | x = −2, y = 3 | (−1, 5) |
| 2 | 응용 | x = 1, y = −2 | (3, −3) |
| 3 | 도전 | x = −1, y = 2 | (1, −1) |

처음에는 미션 1만 선택할 수 있으며 미션 2·3은 자물쇠와 함께 비활성화됩니다. 미션 1 성공 시 미션 2가, 미션 2 성공 시 미션 3이 열립니다. 완료한 미션에는 초록색 ✓가 붙고 다시 방문할 수 있습니다. 미션 이동 시 계수는 (1, 0, 0)으로 돌아가고, 선택 문항과 그래프의 목표점·목표 점근선·좌표·화면 위치가 함께 바뀝니다.

- 슬라이더를 움직일 때마다 자동 판정합니다. **미션 확인하기**는 같은 판정을 수동으로 다시 확인하는 버튼이며 성공에 필수는 아닙니다.
- 현재 p·q 및 실제 함수값을 계산해 목표와 비교합니다. 픽셀 위치나 그래프의 시각적 겹침으로 판정하지 않습니다.
- 목표점의 x에서 분모가 0이면 실패합니다. a=0은 슬라이더에서 선택할 수 없습니다. 절대 오차 허용값은 10⁻⁹이며 세 미션의 0.5 간격 오답과 작은 오차의 오답도 검사했습니다.
- 최초 성공 순간에만 그래프 중앙에 **성공!**이 부드럽게 나타납니다. 그래프는 유지하며, `setTimeout(..., 1000)`으로 1초 후 알림을 숨깁니다. 브라우저가 비활성 탭의 타이머를 지연하는 경우에는 실제 표시 시간이 늘어날 수 있습니다.
- **다음 미션**은 알림이 사라진 뒤 활성화됩니다. 자동 이동하지 않으며, 마지막 미션에서는 비활성화됩니다.
- 미션 선택 버튼은 선행 미션 성공 즉시 해제됩니다. 알림 도중 미션을 직접 선택하면 기존 타이머와 알림을 취소합니다. 완료한 미션의 재성공에는 알림이 반복되지 않습니다.
- 정답 계수·함수식·해설은 해당 미션을 성공하기 전에는 공개하지 않습니다. **정답 해설** 버튼도 성공 전에는 비활성화됩니다. 학생이 직접 만드는 현재 함수식은 항상 표시합니다.
- 세 미션을 모두 완료하면 **축하합니다! 유리함수 그래프 챌린지의 모든 미션을 완료했습니다!**를 표시합니다. 진행 상황은 **3개 중 2개 완료** 형식입니다.
- **처음부터 다시 도전**은 활동 4의 완료 기록·객관식 기록, 잠금, 알림 타이머와 제출 상태를 초기화하고 미션 1로 돌아갑니다. 활동 1~3의 완료는 유지합니다. 새로고침·탭 종료 후에도 같은 브라우저 저장소에서 완료 기록을 복원합니다.

교사용 검증 순서:

1. 활동 4를 열어 미션 2·3이 잠겨 있는지 확인합니다.
2. **a=2, p=−2, q=3**으로 조절합니다. 즉시 성공하고 알림 종료 후 다음 미션 버튼이 활성화되는지 봅니다.
3. 다음 미션으로 이동해 **a=−2, p=1, q=−2**로 조절합니다.
4. 미션 3으로 이동해 **a=−6, p=−1, q=2**로 조절합니다. a=−6이 입력되고 전체 완료 문구가 나오는지 확인합니다.
5. 이전 미션 재방문 시 완료가 유지되고 알림이 반복되지 않는지 확인한 뒤 **처음부터 다시 도전**으로 재잠금을 확인합니다.

미션 출제 함수는 목표점이 수직점근선에 놓이거나 해가 a=0인 경우, 슬라이더 범위·간격으로 만들 수 없는 경우를 거부합니다.

## 그래프 조작

- 활동 1~3의 a: −5~5, 활동 4의 a: **−10~10**. 모두 0 제외, 0.5 간격입니다. p·q는 모든 활동에서 −5~5, 0.5 간격입니다.
- 휠 또는 ＋/− 버튼으로 확대·축소, 드래그로 이동합니다. 태블릿은 버튼과 한 손가락 드래그를 지원합니다. 핀치 확대는 구현하지 않았습니다.
- 그래프 위 마우스·터치의 x에 대응하는 함수 좌표 `(x, f(x))`를 표시합니다.
- 두 축의 단위 길이는 같고 격자는 정사각형입니다. 확대 수준에 따라 눈금 간격이 바뀝니다.
- 점근선 양쪽 가지를 나눠 계산하므로 x=p에서 연결되지 않습니다. 화면 밖의 큰 값을 걸러 그리고 화면 경계 교점을 추가합니다.
- 확대 범위는 단위당 10~300픽셀, 이동 중심은 ±10,000입니다. **화면 초기화**는 현재 활동의 기본 화면 위치로 돌아갑니다.

| `math.js` | 기존 `A_VALUES`와 확장 `MISSION_A_VALUES`, 수식·좌표·가지 계산, `makeMission` 및 `checkMission` |
| `index.html` | Preview·배포용 생성 파일 |
| `tests/` | 수학·브라우저·미리보기 회귀 검사 |

원본을 수정한 뒤 아래 명령으로 완성 HTML에 반영하세요. 외부 패키지는 필요 없습니다.

```sh
python3 tools/build.py
python3 tools/build.py --check
```

Windows에서는 `py tools/build.py`를 사용하세요. `index.html`만 직접 수정하면 다음 생성 때 덮어써지므로 원본을 수정하는 편이 좋습니다.

미션은 `app.js`의 `missions` 배열에서 수정합니다. 각 `M.makeMission(p, q, x, y)`는 목표 점근선과 목표점으로 정답 a를 계산하며, 목표 표시·문항·판정·해설은 선택한 미션에서 자동으로 가져옵니다. 3개 미션의 순서와 개수는 이 챌린지의 고정 구성입니다. 계수 범위를 바꿀 때에는 `math.js`의 계수 목록과 `app.js`의 활동별 범위 설정도 함께 점검하세요.

## GitHub Pages 무료 배포

파일 업로드부터 버튼별 설정까지의 자세한 안내는 [GITHUB_PAGES.md](GITHUB_PAGES.md)를 참고하세요.

이미 배포된 저장소는 수정본을 main에 반영하면 기존 Pages 설정에 따라 다시 배포됩니다. Pages 설정은 변경하지 않습니다.

1. 수정했다면 `python3 tools/build.py`로 `index.html`을 갱신합니다.
2. 파일을 GitHub 저장소 `main` 브랜치 최상위에 올립니다. 실행에는 `index.html`만 있으면 되며 유지보수 원본도 함께 보관하세요.
3. **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
4. **main**, **/(root)**를 선택하고 **Save**를 누릅니다.
5. Pages에서 제공하는 배포 주소를 열고 네 활동·슬라이더·객관식·미션을 확인한 뒤 공유합니다.

저장소 공개 여부와 요금제에 따라 Pages 사용 가능 여부가 달라질 수 있습니다. 비밀 키나 별도 데이터 서버는 필요 없습니다.
